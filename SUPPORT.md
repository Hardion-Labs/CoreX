# Support

CoreX is an early-stage project. Its documentation describes the current scaffold and planned direction; planned subsystems should not be treated as available features.

## Documentation

- [README](README.md): project overview, current status, build commands, and roadmap.
- [Architecture](docs/architecture.md): initial principles and planned subsystem boundaries.
- [Coding standards](docs/development/coding-standards.md): conventions for contributions.
- [Contributing](CONTRIBUTING.md): development and pull request process.

## Bugs

Use the repository's [bug report form](.github/ISSUE_TEMPLATE/bug_report.yml) for reproducible defects. Before filing, search existing issues for a matching report. For a suspected security vulnerability, follow [SECURITY.md](SECURITY.md) instead; do not disclose it in a public issue.

Include enough information to reproduce the problem:

- What you did and the exact steps to reproduce it.
- What you expected and what actually happened.
- Zig version, operating system, and machine architecture.
- Relevant command output or logs, with secrets and personal information removed.
- A small example or project state that demonstrates the issue, if possible.

## Feature requests

Use the [feature request form](.github/ISSUE_TEMPLATE/feature_request.yml). Describe the problem and who it affects, rather than only prescribing an implementation. For changes with broad architectural impact, discuss the proposal before submitting code.

## General questions

Use GitHub issues for project questions that are relevant to the repository and can be discussed publicly. This repository does not declare a separate support email address or community chat.

## Security

See [SECURITY.md](SECURITY.md) for private reporting guidance. Do not post vulnerability details in public issues.
